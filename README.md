# 游泳滑轨机器人视觉控制 APP

`vision_app` 是电脑端视觉与运动控制程序。当前真实电机路径使用 TCP 连接控制端，默认地址为 `192.168.1.177:8888`；`motor_tcp_client.py` 和下位机程序保持不变。

> TCP 第一版只有命令通道，没有实际转速、堵转或驱动故障反馈。界面中的机器人速度是根据最后成功下发的 RPM 计算出的“指令估算值”，不能当作实测值。真实运行必须配备物理急停，并确认下位机或驱动器具有失联停车能力。

## 五层结构

```text
FrameSource（画面接收）
  -> FrameProcessor（降采样、框外统计和三区分层增强）
  -> TargetTracker（CSRT 框选和跟踪）
  -> MotionController（目标偏差到期望线速度）
  -> MotorCommandGateway（线速度/RPM换算、限幅和发送）
  -> 独立 motor_supervisor 进程
  -> TCP 电机控制端
```

GUI 只组合各层并显示状态。摄像头、OpenCV 跟踪、运动计算和 TCP 协议可以分别测试和替换。

画面处理默认将工作分辨率限制在 `640×360` 以内，以为分层增强和 CSRT 留出实时处理预算。用户先在未增强的缩放画面上框选未知目标；程序排除目标框及保护环统计背景色偏，然后在同一帧生成三区跟踪画面：框内执行自适应 Gamma、局部 CLAHE 和受限锐化，保护环轻微模糊，远背景受限模糊，区域边界采用羽化融合。该画面用于初始化并逐帧更新 CSRT，而不是只用于显示。首次使用或改变处理分辨率后，必须按工作画面重新标定“像素/米”和目标像素偏移，再连接真实电机。

## 视觉处理算法

视觉链路采用“先定义目标，再按目标位置处理画面”的方式，不包含通用目标检测器。目标未知时，用户先在仅完成固定缩放、尚未增强的画面上手动框选；程序随后对同一帧执行增强，并使用增强结果初始化 CSRT。后续帧根据最近两次目标观测预测当前处理框，再生成同类型增强画面供 CSRT 更新。预测位移在水平、垂直方向分别限制为目标框宽、高的四分之一，避免一次错误观测使处理区域突然偏离目标。

### 1. 框外统计白平衡

系统将目标框向外扩展其宽、高的 `30%` 形成保护区，只使用保护区外的水体背景估计 B、G、R 通道增益。统计图宽度不超过 `320 px`，默认每 `4` 帧重新统计一次；亮度最低和最高的 `5%` 像素以及高亮中性像素会被排除。候选增益经过范围限制和时间平滑，以减少气泡、反光或光照变化造成的逐帧色彩闪烁。

白平衡的作用是校正整幅工作画面的水下色偏。它不会恢复相机已经没有记录到的颜色信息，因此增益受到限制，不能把该步骤理解为真实颜色复原。

### 2. 三区分层处理

白平衡后，画面按照目标位置划分为三个处理区域：

| 区域 | 处理方式 | 目的 |
| --- | --- | --- |
| 目标核心区 | 自适应 Gamma、局部 CLAHE、气泡约束锐化 | 增强目标亮度、局部对比度和轮廓 |
| 30% 保护环 | 标准差 `0.70` 的弱高斯模糊 | 保留目标邻域结构并容纳短时预测误差 |
| 远背景区 | 高斯标准差取 `max(2.2, 目标框对角线/120)` 并封顶为 `3.0`，模糊结果以 `0.65` 权重与原图混合 | 削弱气泡、泳道线和池壁纹理的高频干扰 |

远背景并非完全抹除。保留部分原始背景可以让 CSRT 继续获得区分前景和背景所需的负样本信息。

### 3. CIELAB 亮度通道增强

目标核心区先从 BGR 转换到 CIELAB 色彩空间。CIELAB 包含表示明暗的 `L` 通道，以及表示绿—红、蓝—黄颜色关系的 `a`、`b` 通道。程序只处理 `L` 通道，保留原来的 `a`、`b` 通道，以减少直接分别增强彩色通道造成的新色偏。OpenCV 将 `L` 通道映射为 `0～255` 的整数，因此下列阈值均以这一范围为准。

目标处理依次执行以下条件判断：

1. 当目标中位亮度位于 `(2, 105)` 时，根据中位亮度计算 Gamma，并限制在 `[0.75, 1.0]`。Gamma 小于 1 用于提亮暗部。
2. 当第 95 与第 5 百分位亮度之差小于 `90` 时，在 `6×6` 局部网格上执行 CLAHE；动态范围越小，对比度限制越大，但不超过 `2.60`。
3. 使用拉普拉斯方差评价清晰度。方差小于 `80` 时锐化强度为 `0.35`，位于 `[80, 160)` 时为 `0.20`，达到 `160` 后不再锐化。
4. 当气泡风险指标大于 `0.010` 时，锐化强度缩小到原来的 `35%`；高亮中性像素比例超过 `8%` 时关闭锐化，避免强化水花与反光边缘。

Gamma 使用 256 项查找表完成。对输入亮度 `i=0…255`，程序预先计算：

```text
LUT[i] = 255 × (i / 255) ^ gamma
输出亮度 = LUT[输入亮度]
```

视频处理时只需按像素值查表，无需对每个像素重复执行幂运算。

### 4. 羽化融合与 CSRT 输入

如果直接拼接锐化区域和模糊区域，目标框边缘会形成随目标移动的矩形接缝。系统在区域边缘设置渐变过渡带，使不同处理结果按像素到边界的距离平滑混合。羽化宽度取目标框较短边的 `6%`，并限制为 `3～16 px`。

概念上，最终跟踪输入可以写成：

```text
I_track = M_target × I_target + M_guard × I_guard + M_background × I_background
M_target + M_guard + M_background = 1
```

`M_target`、`M_guard` 和 `M_background` 是逐像素渐变权重。融合后的 `I_track` 用于 CSRT 的首次初始化和后续逐帧更新，不是只用于界面显示。渲染器绘制的目标框、中心线和安全区仍只存在于显示副本中，不会反馈给跟踪器。

以上阈值均为当前工程中的经验设置。它们用于形成可运行的实时框架，并不等同于已经证明跟踪准确率提高；正式对照实验应在相同视频、初始目标框、工作分辨率和 CSRT 参数下比较 `增强处理` 与 `不处理（对照）`，记录中心误差、交并比、首次失跟时间、人工重选次数及单帧耗时。

## 安装和启动

Windows 推荐使用仓库自带的一键启动器。电脑只需预先安装 Python 3.11～3.14：

```powershell
run_app.bat
```

也可以在资源管理器中直接双击 `run_app.bat`。第一次运行会自动创建 `.venv` 并安装依赖；后续直接启动 APP。只有 `requirements.txt` 发生变化时才会再次更新依赖，不需要手动激活虚拟环境。

手动启动方式：

```powershell
cd D:\你的路径\Swimmer_Tracker
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m vision_app
```

也兼容 IDE 的“运行 Python 文件”以及直接执行入口文件：

```powershell
.\.venv\Scripts\python.exe vision_app\swimming_app.py
```

Linux/macOS：

```bash
cd /path/to/Swimmer_Tracker
python -m pip install -r requirements.txt
python -m vision_app
```

上述启动方式只依赖项目根目录，不依赖仓库在电脑上的绝对路径。

运行测试：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s vision_app/tests -v
```

Linux 无图形桌面时 GUI 冒烟测试会跳过；纯计算、TCP 和监督进程测试仍可运行。

## 完整使用说明

### 1. 先用 virtual 验证软件

1. 启动 APP，后端选择 `virtual`，点击“连接”。
2. 设置运行模式、换算参数和高级安全参数。
3. 点击“应用并确认参数”。参数修改后确认状态会自动失效。
4. 手动模式可直接启动；视觉模式继续打开摄像头并框选目标。
5. 确认状态栏中的期望速度、换算前 RPM 和实际发送 RPM 符合预期。
6. 点击“停止电机”，确认状态回到“已停止”。

### 2. 手动控制

- `手动 RPM`：填写带正负号的目标转速，适合低速方向测试。
- `手动线速度`：填写 m/s，APP 使用 `RPM/(m/s)` 和电机方向换算目标 RPM。
- 两种模式都会执行 RPM 上限和 RPM 变化率限制。
- 目标值可以在运行中调整；标定、方向、限幅等控制参数不能在运行中修改。

### 3. 视觉跟随

1. 选择 `位置比例跟随` 或 `速度估算跟随`。
2. 填写摄像头索引，例如 `0`；也可以填写摄像头 URL。
3. 点击“打开画面”，再点击“框选 CSRT 目标”。
4. 在弹出的画面中拖动目标框，按 Enter 确认；取消后不会启动。
5. 确认目标偏差、期望速度和方向正确，再点击启动。
6. 目标丢失、摄像头断流或偏差超过安全区域时，APP 会锁存故障并请求停车。

### 4. 离线视频分析与录制

离线分析不要求连接电机，也不会向真实电机发送命令：

1. 点击视频区上方的“上传视频”，选择 `MP4`、`AVI`、`MOV`、`MKV`、`M4V` 或 `WMV` 文件。
2. 上传前在“视觉”选项中选择 `增强处理` 或 `不处理（对照）`；完成一组后关闭画面，切换选项并重新载入同一视频。
3. APP 会停在视频首帧；点击“框选目标”，拖动框选运动员并按 Enter 确认。
4. 点击“开始分析”逐帧播放和跟踪；可随时点击“暂停分析”停在当前帧。
5. 点击“开始录制”，在系统保存对话框中自定义目录和文件名。录像包含目标框、中心线和安全区等分析叠加层。
6. 再次点击“停止录制”完成写入。视频播放结束时也会自动释放并保存录像文件。

实时相机画面同样支持录制。录像支持 `.mp4` 和 `.avi`；若没有填写扩展名，默认保存为 `.mp4`。

### 5. 连接真实 TCP 控制端

1. 先运行 [motor_tcp_client.py](motor_tcp_client.py)，确认目标设备能接收 `S/P/T` 命令。
2. 关闭命令行客户端，避免两个程序同时占用控制连接。
3. APP 后端切换为 `tcp`，填写设备 IP 和端口；默认是 `192.168.1.177:8888`。
4. 点击“连接”后，APP 会先发送 `P`、`T0`，不会自动启动运动。
5. 首次测试只使用很低的手动 RPM；方向、停车和失联保护验证通过后再使用视觉模式。

### 6. 停车、故障与退出

- 正常停车：点击“停止电机”，APP 会重复请求 `P`。
- 故障停车：排除原因后点击“确认故障并复位”，不会自动恢复上次运动。
- 关闭窗口：运行中会要求再次确认，并在关闭 TCP 前发送停车命令。
- TCP 无反馈，因此“停车命令已发送”不代表已经测量确认电机静止。

### 7. 参数保存位置

参数会保存到当前用户配置目录：

- Windows：`%APPDATA%\SwimmerTracker\settings.json`
- Linux/macOS：`~/SwimmerTracker/settings.json`

旧配置中的串口或直接 CAN 后端会迁移为安全的 `virtual`，不会自动连接 TCP。

## 推荐操作顺序

1. 选择 `virtual` 或 `tcp`，填写 TCP 地址后连接。
2. 选择运行模式并填写基础/高级参数。
3. 点击“应用并确认参数”。参数发生变化后必须重新确认。
4. 手动模式可直接启动；视觉模式需先打开摄像头并框选 CSRT 目标。
5. 阅读启动风险提示并启动，运行中可随时点击停止。
6. 故障发生后先排除原因，再点击“确认故障并复位”；程序不会自动恢复运动。

## 后端

- `virtual`：软件仿真，不驱动真实设备，并提供仿真测量反馈。
- `tcp`：唯一真实后端。发送与 `motor_tcp_client.py` 相同的换行文本协议。

TCP 命令：

```text
S       启动
P       停止
T600    期望转速 +600 RPM
T-600   期望转速 -600 RPM
```

连接后先发送 `P`、`T0`；启动时发送 `T0`、`S`；运行时默认每 50 ms 更新 `T`；停车、故障和退出都会重复请求 `P`。程序不会自动重连，也不会在 TCP 失败后切换到 virtual。

## 运行模式

### 手动 RPM

直接输入期望 RPM。命令仍经过协议范围、用户 RPM 上限和变化率限制，适合低速联调。

### 手动线速度

输入期望线速度，第一层按下式换算：

```text
期望RPM = 电机方向 × 期望线速度 × RPM/(m/s)
```

### 位置比例跟随

默认让目标框中心保持在画面中心，也可以设置目标像素偏移：

```text
参考位置 = 画面宽度 / 2 + 目标偏移px
偏差m = 相机方向 × (目标中心x - 参考位置) / 像素每米
期望速度 = 位置P增益 × 偏差m
```

偏差进入死区后输出零速，结果受最大线速度限制。

### 速度估算跟随

对目标相对位移序列做线性拟合，估算相对速度：

```text
机器人估算速度 = 电机方向 × 最后发送RPM / RPM每米每秒
运动员估算速度 = 机器人估算速度 + 目标相对速度
```

该模式使用指令值估算机器人速度，不是闭环测量。

## 参数与安全

基础参数包括 TCP IP/端口、摄像头源、运行模式、手动目标、像素/米、RPM/(m/s)和位置 P 增益。高级区域包括方向、目标偏移、死区、速度/RPM上限、RPM变化率和速度估算窗口。

控制参数修改后必须重新确认。运行中切换模式或修改控制参数、TCP 断线、命令超时、摄像头断流、CSRT 丢失、目标越过安全区域或计算异常都会进入锁存故障。故障不会自动恢复。

本地视频只允许配合 `virtual`；APP 禁止用离线视频驱动真实 TCP 电机。旧配置中的 `arduino_serial` 或 `python_can` 会安全迁移为 `virtual`，不会自动连接真实设备。

## 首次实机检查

1. 架空滑轨或断开机械负载，并确保物理急停可触达。
2. 用 `motor_tcp_client.py` 验证 TCP 地址和 `S/P/T` 协议。
3. 在 APP 中先用 `virtual` 验证四种运行模式。
4. 切换 TCP，只用很低的手动 RPM 验证正反方向和停车。
5. 断开网络验证下位机失联停车；若断线后仍保持转速，不得进入视觉运行。
6. 实测像素/米、RPM/(m/s)、安全速度、死区和位置增益，再进行载荷测试。
